# Lua 开发规则

## Lua 文件结构与注释

手写 Lua 文件按以下顺序组织，沿用 `phantom/lua/runtime/` 的分区标记；没有声明的分区也保留标记：

1. 文件头：使用 Lua 长注释，必须包含 `original`、`uuid`、`摘要`、`描述`、`修改记录`。
   - `original` 记录相对 `phantom/lua/` 的源码路径，沿用 `runtime\01_addon.lua` 格式，生成副本随机改名后仍保留该值供溯源。
   - 手写源码 `uuid` 已有唯一值时保留，不因补注释或生成产物重新生成；runtime/general 的生成副本单独分配全新 UUID4，并只更新副本文件头 uuid 以匹配文件名。
   - `摘要` 简要说明文件用途；`描述` 详细说明本文件承担的功能和业务流程。
   - 保留已有的 `runtime_index` 等元数据与历史记录，不编造历史。
   - `修改记录` 仅在新增或修改业务逻辑时增加；修复 bug、增减注释不增加记录。
2. `namespace initialization`：固定只有 `local addonName, addonTable = ...`。
3. `api cache`：集中本地化文件中使用的 WoW 官方 API 与 Lua API，每项声明使用中文行尾注释说明用途。官方全局对象、枚举引用也在此集中声明；通过对象调用的方法保留原有调用方式。
4. `variable reference`：集中声明插件内部的跨文件本地引用，每项使用中文行尾注释说明用途。引用必须保留原有初始化时机；运行期变化的状态不能缓存成加载期快照，仍通过共享表读取或写入。
5. `logical code`：按业务流程组织代码，为有业务含义的变量、步骤和分支补充必要的中文行尾注释；`end` 等结构行不强制加注释。

补全注释和 API 本地化必须保持业务行为、调用顺序与状态更新方式不变，不借此重构或修复其他逻辑。描述以当前实现和已核验事实为准，不把预期行为写成已实现的保证。

生成条件实例各自为独立 Lua chunk，生成器在模板前加入标识、职业专精守卫和统一 namespace，不添加外围 do/end；模板内部结构保持不变。宏绑定独立成文件，使用函数调用避免最大宏数量下累积 chunk 局部变量。输出与 TOC 顺序见[生成器落地](architecture.md#生成器落地)。

### 核心 API 说明

新增或修改核心 WoW API 调用时，使用 [WoW 核验与注释要求](../../phantom-wow-api/references/source-verification.md#api-comments)。

### Cell 初始化与刷新

以下约定沿用 `phantom/lua/general/` 已建立的 Cell 实现风格，适用于后续 Cell 文件：

- 每个文件使用独立的局部 `eventFrame` 承载自身刷新逻辑，不与其他文件共用事件框架。
- Cell 构造函数必须注册到 `UIInitFuncs`，在共享尺寸和背景初始化后执行，沿用现有缩放及布局计算，不在文件加载时直接构造 Cell。
- 优先通过相关事件刷新；支持单位过滤的事件应按业务需要使用 `RegisterUnitEvent`。需要持续轮询的状态才使用节流的 `OnUpdate`。
- 使用 `OnUpdate` 时，将 `math.random` 缓存为 `random`，每个文件独立以 `local fastTimeElapsed = -random()` 初始化计时，推迟首次刷新以实现随机错峰，不修改全局随机种子。
- 累加 `elapsed`，超过刷新间隔时扣除一个间隔并刷新一次，保留剩余累计时间，每帧最多刷新一次。通用状态 Cell 沿用 `0.1` 秒间隔；构造后保持默认黑色，等待错峰首次刷新。
- 刷新函数必须避免访问尚未构造的 Cell；每次读取当前共享状态，事件和轮询回调只更新已有实例。

### 未使用声明清理

- 只有用户明确下达清理指令时，才执行未使用声明清理；未下达指令时，不得主动或顺带清理。
- 清理必须使用 Luacheck 检测未使用的局部变量及赋值后未读取的局部变量，可运行 `luacheck phantom/lua --no-config --codes --no-color --only 211 231`，或将路径替换为用户指定范围。
- 只清理 `api cache` 和 `variable reference` 分区内经检测确认未使用的声明；其他分区的声明即使被报告也不在清理范围内，分区标记必须保留。
- 删除前核对初始化表达式，不能因删除声明而丢失有副作用的调用；不得扩大为业务逻辑重构。
- 清理后重新运行 Luacheck，确认这两个分区没有剩余的未使用声明，并对涉及的 Lua 文件执行语法检查。
