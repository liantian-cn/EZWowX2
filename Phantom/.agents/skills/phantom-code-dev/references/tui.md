# TUI 规范

## 入口与默认状态

主程序通过 `python -m phantom.main` 启动；加载应用配置、检测游戏、展示通用数据，按职业专精管理多份 rotation 并共同生成插件。

程序启动后默认暂停：截图、解码与数据展示都由综合页的“启动”按钮开始，“关闭”按钮停止采集及持续执行并保留界面，Ctrl+Q 退出程序。

## 应用配置

应用配置是启动工作目录（`Path.cwd()`）下的 `phantom.toml`，与程序目录、源码目录和 rotation 文件位置无关，程序不改变工作目录。rotation 配置的 schema 见 [configuration.md](../../phantom-rotation-dev/references/configuration.md)，两者是不同的文件。

- 目录内没有该文件时写入默认内容；只在启动时读取，不做热更新。除 rotation 自动选择回写外，不补写已有文件的缺失字段。
- 普通字段缺失使用默认值；文件语法、普通字段类型或首次创建/读取错误在进入界面前明确报告并以非零状态退出。rotation 组合键/单项路径的局部错误及选择回写失败使用下文警告与回退规则，不阻止其余组合使用。

| 字段 | 默认值 | 约束 |
| --- | --- | --- |
| `capture.plugin` | `"gdi@dev"` | 精确版本标识，启动加载；显式错误不回退 |
| `capture.fps` | `15` | 有限正数，用作截图与界面读取最新快照的频率上限 |
| `keyboard.plugin` | `"post_message@dev"` | 精确加载键盘后端；选择错误不回退 |
| `ui.min_width` | `120` | 正整数，界面最小宽度（列） |
| `ui.min_height` | `46` | 正整数，界面最小高度（行） |
| `ui.log_max_lines` | `1000` | 正整数，业务日志保留的最大物理行数 |

## 视觉

界面固定使用 Phantom 纯黑深色配色，不跟随系统或终端深浅色，也不提供主题切换入口。

- 主背景使用 `#000000`，容器使用 `#111111`，正文使用 `#EDEDED`，选中与强调使用 `#FFFFFF`。
- 正常状态使用 `#4ADE80`，暂停和未运行使用 `#A1A1AA`，警告使用 `#FBBF24`，错误使用 `#F87171`。

## 布局

- content 填满 footer 之外的剩余空间，footer 贴底、高度由内容决定，并且只包含一行 `status_line`。
- `status_line` 左对齐，各项之间使用 ` · ` 分隔。
- 终端尺寸小于配置的最小值时，content 显示当前尺寸与要求的尺寸，footer 保持可见；恢复尺寸后回到原来的标签页与运行状态。

## 页面与操作

标签页顺序固定为：综合、通用条件、日志、宏绑定、循环条件；默认显示综合。

| 按键 | 行为 |
| --- | --- |
| Tab / Shift+Tab | 在标签页之间循环切换 |
| ↑ / ↓ | 在可用按钮之间移动选择 |
| Enter / Space | 激活当前按钮 |
| Ctrl+Q | 退出程序 |

鼠标操作同样可用。宏绑定页仍为占位；循环条件页展示当前匹配 rotation 的条件名称、插件名称、返回值，综合页一次生成全部已加载 rotation。

## 综合页

页面分为约 1:3 的左右两栏：

- 左栏“操作”：启动、关闭、生成插件，以及键位说明。
- 右栏“当前工作状态”：程序状态、游戏状态、采集状态、画布宽高、配置 FPS 和当前问题。

## 通用条件页

表格固定两行，顺序为玩家职业、玩家专精，来自同一次有效截图的 `getCell(1..2, 1)`。第一行其他三个 Cell 仍由 Lua 输出；其 Python 状态插件只在配置声明后出现在循环条件页，使用配置中的 title 展示业务值。

| 列 | 内容 |
| --- | --- |
| 项目 | 通用字段名称 |
| RGB | Cell 的 `color_string` |
| 亮度值 | 仅当 `is_pure` 为真时显示 `mean`；非纯色显示 `—` |
| 显示值 | 当前阶段固定为空 |

暂停、截图失败或解析失败都清空已有原始值，不保留过期数据；恢复后由新的有效帧重新填充。

## 日志页

业务日志是与 Textual、Python 诊断日志分离的独立通道，只通过 `log(message: str)` 写入，不写入每帧数据。

- 写入时添加本地 `[HH:MM:SS]` 时间戳，并在加时间戳之前丢弃与上一条完全相同的正文。
- 最多保留 `ui.log_max_lines` 行物理行，超出时淘汰最旧的行；日志填满页面空间并可滚动。
- 记录程序启停、游戏状态变化、采集失败与恢复，以及停止失败等业务事件。

## 游戏检测

游戏状态由后台线程每秒独立检测一次，判定为：进程名大小写不敏感等于 `wow.exe`，且可执行文件的直接父目录为 `_retail_`。不绑定盘符、安装路径或进程数量。

- 没有任何确认匹配的进程时禁用“启动”。
- 无法读取可执行文件路径的候选进程不能算作游戏正在运行，并在界面说明原因。
- 游戏退出时停止采集并清空数据；游戏重新启动后不自动恢复采集，需要再次手动启动。

## 采集生命周期

采集通过 `phantom/core/capture/registry.py` 按 `capture.plugin` 创建 worker，并复用最新结果快照：按配置 FPS 读取最新快照并解码，不排队历史帧。进程查询和阻塞停止都不在 UI 线程执行，界面通过 Textual 消息更新。

- 截图 worker 提供只读运行状态，用于区分可恢复的定位、校验错误与线程已结束。
- 线程致命结束时暂停程序、显示失败原因，并允许用户显式重新启动。
- 关闭按钮、游戏退出和应用退出共用同一套清理流程：停止期间禁用启动、等待资源释放、拒绝暂停后到达的过期结果；进程退出前等待后台线程结束。

## 范围与待定事项

- 本阶段不增加 rotation 选择表格和包名输入，选择仅由应用配置管理。
- 宏绑定页（后续绑定阶段）。


## 多份 rotation 与生成（2026-09-19 确认）

应用配置使用 `[rotations]` 平铺组合键，例如 `"deathknight.blood" = "rotations/死亡骑士-鲜血.toml"`；键来自固定的 13 职业、40 专精集合（含 demonhunter.devourer）。每组合至多加载一份，不要求配齐。旧 `[rotation].path` 不兼容、不迁移，发现后警告且忽略。
路径相对于应用配置目录解析，也允许绝对路径；wow.executable 默认为空，addon.name 默认为 Phantom，包名匹配 [A-Za-z][A-Za-z0-9_]*。
启动优先加载显式选择；缺失或失效则扫描同级 `rotations/*.toml` 顶层，按文件名稳定排序选该组合第一份有效候选。无效文件或非法组合跳过并警告；目录不存在或为空不创建示例。显式路径不受扫描范围限制。
发现候选仅解析元数据，未选候选不补写默认参数；实际加载仍遵守[条件默认值回写规则](../../phantom-rotation-dev/references/configuration.md#条件参数默认值与加载回写)。同一组合选定有效文件后不再加载其他候选。
自动选择成功后回写 phantom.toml，保留无关字段和注释，使用并发源检查及单文件原子替换。回写失败警告，本次内存选择仍有效；找不到替代项时保留原显式配置，该组合不可用。
不同已选文件 UUID 冲突按稳定顺序保留首份，后续文件生成不冲突的 UUID4 并保存后再完整加载；不修改未选候选。UUID 保存失败按候选加载失败继续寻找替代，不仅在内存中换 UUID。
配置和 rotation 修改均需重启生效；生成使用本次启动已成功加载的集合，不重新读取 rotation。没有可用 rotation 或游戏路径时禁用生成并说明原因。生成失败不使已加载内存配置失效。
采集、停止、生成或退出期间禁止重复生成，生成期间禁止启动采集；正常退出等待生成结束。
输出路径为 Wow.exe.parent/Interface/AddOns/addon.name，要求现存 _retail_/Wow.exe。
全部已加载组合共同生成一个包，按专精目录拆分条件实例与独立宏文件，共享 runtime/general/media。每次生成 Lua 文件名为全新随机 UUID4；完整预准备和输出树安全检查成功后清空本 addon 全部内容，清理或写入失败立即停止，TOC 最后发布。目录、顺序及失败边界见[生成器落地](architecture.md#生成器落地)。
后台同一帧完成职业专精路由、条件解码、决策和发送，快照携带所选 rotation。无匹配不发键、保持检测，有匹配后自动恢复；用户手动暂停不自动解除。
条件页随匹配项重建；暂停、无有效截图或越界时清空返回值与决策，无匹配不展示旧 rotation 为当前配置。
底栏保留程序/游戏状态，追加匹配 rotation 的 profile.title；手动暂停保留名称，未识别和无匹配明确提示，长名称截断以维持单行。
共享 runtime 监听玩家实际专精变化，弹出仅“重载界面”按钮的标准弹窗，无取消/关闭/Esc 关闭，点击直接 ReloadUI。初始化同专精事件不弹窗，不做持续重弹、Lua 热切换、身份协议或等待重载停键。用户接受弹窗到重载间仍可能发键的边界；Python 不额外识别等待重载状态。
条件状态展示后台实际使用的同帧决策；生成包含宏绑定，运行中命中宏会派发按键。

## 条件、决策与执行（第 14–17 步）

循环条件页展示 rotation 标题、同帧条件值、首个命中的规则序号、表达式、说明、宏名称及键位。
配置有效 rotation 时，启动采集同时启动独立 RotationRuntime；无 rotation 时保留仅采集。每个新帧至多一次求值与发送，界面只展示后台交付的同轮结果，不另行求值。
决策整合进综合页“启动”后的运行流程；不提供独立的“单次试运行”按钮。
日志在已派发宏变化时输出宏名称，Idle 输出无动作；沿用业务日志连续正文去重，不逐帧记录条件值。
无命中时显示 Idle 和无动作；暂停、截图／解析失败、职业专精不匹配或重新加载 rotation 时清空旧决策。
Lua 启用、爆发和延迟通过显式配置的条件插件进入表达式，在循环条件页按配置标题展示；不增加隐式执行门控。示例首条规则显式将未启用或正在延迟映射为 Idle。

键盘目标缺失/歧义、派发失败、执行异常和截图线程结束时暂停，记录原因，修复后手动启动。临时无效截图或条件不可用只跳过本帧。关闭及退出先禁止新组合派发，再在后台等待当前组合释放和所有线程结束，期间界面保持响应。暂停后不展示迟到决策。
