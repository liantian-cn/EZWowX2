# Shigure 源语义与版本索引

本文保存 2026-09-19 单次授权核验的可复用经验。默认迁移直接使用这些记录与用户输入；遇到未覆盖语义先报告，另获授权再查外部。路径与行号用于追溯当时 revision，不保证适用于其他版本。

## 输入与执行

- `Rules` 是优先级序列，首条命中决定当轮动作；保留源相对顺序。盘点每条 `Enabled`，禁用项仍须记录排除理由，不能默认重新启用。
- 主条件与 `SubConditions` 是 **主 AND（子 OR）**，子条件之间不是 AND。源表达式 `&&` 优先于 `||`，迁移为 Phantom `and`、`or` 时显式加括号保留分组。
- “暂停”映射当轮 `Idle`，不是持久暂停或另需恢复的开关；空 `Step` 不能推导等待时长。
- 本次输入没有 `ContinueLogic`、`DelayMs`、`LogicDelayMs`。未来出现这些字段时，当前首命中和无等待经验不足以覆盖，须先查明，不能忽略。
- 分别记录“判断对象”“动作对象”“判断技能 ID”“实际宏动作”；它们可以不同。源疑似错误列入审计，不自行统一。
- `Unit=31/32/33` 分别为 `player/target/focus`；动作宏使用相应 `[@unit]`。未声明 `Unit` 的动作保留普通宏。
- JSON 中英雄天赋适用范围是输入约束，应记录原字段和值；不把它变成 Phantom 尚未实现的路由，也不能宣称覆盖源范围外的天赋。

## 技能与光环引用

| 源引用 | 含义与迁移检查 |
| --- | --- |
| `spells.ID.count` | 充能；核对 `spell_charges` 的显示量程与比较谓词 |
| `spells.ID.cooldown` | 冷却；本次源将只有 GCD 的状态编码为 0，因此 `ignore_gcd=true` 有来源依据 |
| `auras.Unit.ID.value` | 时长显示编码，不是可直接跨系统比较的精确秒数 |
| `auras.Unit.ID.apps` | 层数；量程、饱和与来源筛选仍须核对 |

技能 Lua 的多 ID 组是同一观测槽的别名；C# 状态构造把槽值映射给全组 ID。表达式只写一个 ID，也必须保留该 ID 所属完整组，不能仅取表达式里的 ID。本次已确认组：

| 名称 | 完整别名组 |
| --- | --- |
| 破灭 | `[441426, 447954, 441424, 441378, 441416]` |
| 午夜舞步 | `[1264351, 1264405, 1264568, 1264407]` |
| 沸点 | `[1265790, 1265982, 1265968]` |
| 赤色天灾 | `[81141, 81136]` |

源光环使用 `PLAYER` 来源过滤；其含义包含玩家、玩家宠物和载具，不是仅 `sourceUnit == "player"`。源光环门控先要求单位存在：`HELPFUL`／`HELPFUL|PLAYER` 还要求可辅助；`HARMFUL`／`HARMFUL|PLAYER` 要求可攻击且不可辅助。这与 Phantom 当前各插件不完全相同，复用时需核对精确契约，不据名称判定等价。

## 数值、哨兵与近似

- “战斗时间 == 0”按迁移政策解释为玩家脱战；“引导 != 0”表示正在引导，“引导进度 == 0”按未引导处理；“施法（正计时）”及蓄力按相应活动状态理解。现有 `player_cast_progress` 合并施法和引导，返回 0 还可能包含刚开始时的量化窗口；相邻的相同暂停动作可在确认后合并为 `>0 → Idle`，蓄力独立保留。
- 单位类型与动作 `Unit` 不是同一编号体系。源类型 0 还包含死亡及既不可攻击也不可辅助的单位；`>100` 表示可辅助，`0<类型<100` 表示存活、可攻击且不可辅助。不能直接拿 `UnitIsEnemy` 代替这一组合。

- 光环 `value`：不存在为 0，存在至少为 1，永久通常为 255；255 还可由显示饱和产生，不能作为永久的唯一标记。`>=1` 可表达存在，但 `<=1` 同时覆盖不存在和存在时的最小编码，不能改写为仅不存在。
- 冷却源编码：仅 GCD 为 0，禁用为 254，无效为 255。Phantom 的 375 兜底与其在本次 `==0` 谓词下等价，仅表示都不就绪；其他大小比较不得宣称全域等价。
- 源秘密资源曲线在上限 `>=300` 时使用百分比路径，否则按实际最大值；非秘密路径输出原始值，两个路径并非统一单位。先依据输入实际阈值与用户政策确定 Phantom 固定量程，不能照抄秘密分支当成通用资源规范。
- 源目标距离取 LibRangeCheck 的 `maxRange` 上界，是范围估计而非精确几何距离。替换为技能射程改变语义，需冻结映射及边界。
- 源玩家生命使用预测值，目标生命使用非预测值。本次统一预测是用户纠正，不能称完全复现源行为。
- 源战斗时间的连续量化与 `ceil` 版本存在差别；本次将 `time == 0` 按用户决定解释为脱战，不保留刚进战的量化窗口。这是授权覆盖，不是源语义本来如此。
- 源物品状态在物品缺失、冷却数据无效或未启用时编码 255；就绪为 0，正冷却按向上取整秒数编码并在 254 饱和。定义的 `isEquipped=true` 检查装备，否则检查背包数量；不含 usable 检查。本次 `241308` 为背包路径，只比较 `==0`，使用布尔就绪插件即可，不必重建整个整数状态域。

## 源控制状态

源技能爆发初始关闭，`/fu cd` 默认开启 15 秒，`on` 开启 3600 秒；药水有独立 toggle，默认关闭。源延迟默认 1 秒，新请求替换原计时。Phantom 的状态模型及默认值独立，不能照搬开关名就认为行为一致；本次归并策略见[冻结案例](confirmed-tank-migration.md#状态暂停与顺序)。

### 插入请求：经验保留，本次排除

插入法术是请求业务，不是当前施法：`/fu i 技能名或ID` 建立请求，按职业技能 index 比较、替换，1.5 秒超时；非秘密且单位为 `player` 的施法成功事件与请求匹配时清除。命令要求技能存在于职业列表；表达式右侧 spell ID 先映射为 index，不存在映射则不命中。施法失败不在这条成功事件路径立即清除；源专精重建没有查到专门清除，不能声称切专精必定清空。本工具默认不迁移插入法术类，不新增“插入”条件或用施法状态代替；未来明确需要该业务须单独定义并授权。
